# slam360 — 360 영상 촬영 경로 자동 계산 (로컬 파이프라인)

360 카메라로 찍은 영상에서 **카메라 이동 경로(궤적)를 자동 계산**해,
[통합 검토 뷰어](https://trier89.github.io/viewer/)의 "SLAM 궤적 가져오기"로
바로 불러올 수 있는 파일을 만들어 줍니다.

- 엔진: [Stella-VSLAM](https://github.com/stella-cv/stella_vslam) (오픈소스, equirectangular 네이티브 지원)
- 모든 처리는 **내 PC 안에서만** 이루어집니다 — 영상이 외부로 나가지 않습니다
- GPU 불필요. 처리 시간은 대략 영상 길이의 0.5~2배

## 요구사항

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (윈도우/맥) 또는 docker (리눅스)
- 디스크 여유 약 5GB (빌드 이미지)

## 사용법

```bash
# 맥/리눅스
./slam360.sh 현장촬영.mp4

# 윈도우 (cmd)
slam360.bat 현장촬영.mp4
```

최초 실행 시에만 Docker 이미지를 빌드합니다(20~40분). 이후에는 바로 처리됩니다.

완료되면 영상과 같은 폴더에 생성됩니다:

| 파일 | 내용 |
|---|---|
| `현장촬영_trajectory.txt` | 카메라 궤적 (TUM 형식) → **뷰어로 가져올 파일** |
| `현장촬영_slam/` | 원본 로그·맵 데이터(재처리용) |

## 뷰어 연동

1. 뷰어에서 360 영상을 불러온다
2. `SLAM 궤적 가져오기`로 `*_trajectory.txt`를 불러온다 — 초록색 경로선이 표시됨
3. 정렬 패널에서 `360° 영상`을 선택하고 기즈모로 경로를 모델 위치에 맞춘다
   - 단안 SLAM은 절대 크기를 모르므로 **스케일(R)** 보정이 필요합니다.
     영상 속에서 길이를 아는 구간(복도 폭 등)을 기준으로 맞추면 쉽습니다
4. 재생하면 촬영 위치가 경로를 따라 자동 이동합니다

## 옵션

```bash
./slam360.sh 영상.mp4 --keep-res        # 원본 해상도로 처리 (느리지만 정밀)
./slam360.sh 영상.mp4 --frame-skip 3    # 3프레임당 1장 처리 (빠르지만 덜 정밀)
```

기본값은 1920×960으로 축소 + 전체 프레임 처리입니다.

## 촬영 팁 (추적 품질을 좌우합니다)

- **천천히 걷기** — 빠른 회전·뜀걸음은 추적이 끊기는 주원인
- 조명이 밝고, 텍스처 없는 흰 벽만 가득한 구도를 피해 **구조물이 보이게**
- 사람·차량이 많이 움직이는 시간대는 피하기
- 시작 지점에서 2~3초 정지 후 출발하면 초기화가 안정적

## 잘 안 될 때

| 증상 | 대처 |
|---|---|
| 궤적이 안 나옴 / 중간에 끊김 | `--frame-skip 1` 확인, 더 밝은 영상으로 재촬영 |
| 경로가 휘어 있음 (드리프트) | 같은 지점을 한 번 더 지나가게 촬영하면 루프 클로징으로 보정됨 |
| 2:1 경고 | 카메라 앱에서 equirectangular(360) 형식으로 다시 내보내기 |
| 빌드 실패 | `docker build --no-cache -t slam360 .` 재시도, Docker 메모리 4GB 이상 할당 |

## 라이선스
